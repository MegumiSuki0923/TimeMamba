# ETTh1 训练日志自动清洗设计

## 目标

为 `scripts/ETTh1_hybrid.sh` 增加统一日志后处理：只要正式训练模式已经建立日志管道，无论两组训练全部成功还是任一阶段失败，脚本退出时都自动调用现有 `clean_log.py` 生成对应的 `_cleaned.log`。

`--validate-only` 不创建日志，也不调用清洗器。

## 实现范围

仅修改 `scripts/ETTh1_hybrid.sh`，复用现有 `clean_log.py`，不修改清洗算法、训练代码、模型或实验参数。

## 退出处理流程

正式训练模式建立日志管道前，脚本将原始 stdout 和 stderr 分别保存到文件描述符 3 和 4。执行 `exec > >(tee -a "$log_file") 2>&1` 后必须立即执行 `tee_pid=$!`，然后注册 `EXIT` trap；不得在捕获 `$!` 前启动任何其他后台任务。

trap 按以下顺序执行：

1. 第一条命令立即保存进入 trap 时的原始脚本退出码。
2. 注销 `EXIT` trap 防止递归，并执行 `set +e`，保证后续任一清理步骤失败都不会提前中断 trap。
3. 用 `exec 1>&3 2>&4` 将 stdout/stderr 恢复到原始终端；这会关闭当前 shell 在描述符 1、2 上持有的 `tee` 管道写端。随后用 `exec 3>&- 4>&-` 关闭不再需要的保存描述符。
4. 执行 `wait "$tee_pid"` 并显式保存 `tee_status=$?`，确保日志尾部完整落盘。即使 tee 失败也继续清洗。
5. 使用 time-llm 环境的 Python 执行 `clean_log.py "$log_file"`，并显式保存 `clean_status=$?`。
6. 在已恢复的原始 stdout/stderr 上打印原日志、清洗日志、tee 状态及清洗状态；这些消息不再写回原日志。
7. 按退出码优先级计算 `final_status`，最后显式执行 `exit "$final_status"`。

该顺序避免清洗器与仍在写文件的 `tee` 发生竞争，导致 `_cleaned.log` 缺少最后几行。

## 退出码规则

退出码优先级为：

1. 若训练流程原本非零退出，最终保留该退出码；`tee` 或清洗失败只额外报告，不能掩盖训练失败。
2. 若训练流程成功但 `tee` 失败，最终返回 `tee` 的非零退出码。
3. 若训练流程和 `tee` 均成功但 `clean_log.py` 失败，最终返回清洗器的非零退出码。
4. 三者均成功时返回 0。

## 验证

不启动训练。测试在 `/tmp` 创建脚本副本，对副本中的训练命令、tee 命令和清洗命令做机械替换，使用只写固定日志并返回指定状态的受控替身；仓库内正式脚本不增加环境变量覆盖、兼容入口或测试专用分支。临时副本保留与正式脚本完全相同的 trap 函数和文件描述符操作，从而直接验证退出处理实现。

验证矩阵：

- `bash -n scripts/ETTh1_hybrid.sh` 通过。
- `--validate-only` 不生成日志和 `_cleaned.log`。
- 模拟成功退出时，先完整写入日志尾部，再生成 `_cleaned.log`，退出码为 0。
- 模拟训练失败时仍生成 `_cleaned.log`，并保留原训练失败码。
- 模拟训练成功但 tee 失败时仍执行清洗，最终返回 tee 失败码。
- 模拟训练成功、tee 成功但清洗失败时，最终返回清洗失败码。
- 模拟训练失败且 tee、清洗同时失败时仍尝试清洗，最终保留原训练失败码。
- `run_main.py` 与 `clean_log.py` 的实现前后哈希保持不变。
